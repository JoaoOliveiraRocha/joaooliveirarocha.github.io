Misconception #1

"So the harness doesn't matter?"

"No new intelligence" is not "no difference". Same model, different harness:

What changed Result
mimo-v2.5-pro: 3 harnesses mimo-v2.5-pro: OpenCode 44.9% · Pi 48.3% · Cline 60.7%
Prompt, tools vs Harness gpt-5.2-codex: 52.8% → 66.5% on Terminal-Bench 2.0
Per-model harness profile GPT 5.3 Codex 33% → 53%, Opus 4.7 43% → 53%
Opus 4.6: Claude Code vs other harnesses Claude Code ranked last among Opus 4.6 submissions on Terminal-Bench 2.0
Frontier models, big-vendor harnesses success within ~±2%, cost up to 3×
Latest Frontier evals: around 6% points between best and worst setup

At the frontier, gaps under 5% are noise.

~90s. Fair counterweight to the "No." slide: Katz is talking about frontier models on tasks they can already solve. Rows 1-2: LangChain (Improving Deep Agents with harness engineering; Tuning Deep Agents to Work Well with Different Models, Apr 2026). Row 1 is a bundle of changes (prompt, tools, hooks, reasoning budget), not an ablation of one. Row 3: github.com/cline/benchmark-results, terminal-bench/2026-06-open-weights, 89 tasks, pass@1, ONE run per cell, run by the Cline team (vendor bias: Cline came first or tied on every model). Other models in that table: glm-5.2 Cline 68.5 / OpenCode 59.6 / Pi 57.3; minimax-m3 61.8 / 49.4 / 47.2; kimi-k2.7-code 61.8 / 59.6 / 61.8. The ranking between Pi and OpenCode flips depending on the model. Claude Code row: LangChain, "Tuning Deep Agents to Work Well with Different Models" (Apr 2026). Terminal tasks aren't what Claude Code is tuned for and newer releases may have changed it, so frame it as "the vendor's harness isn't automatically best for its own model". Frontier row: HarnessTax, short tasks, no subagents/MCP. Last row: Anthropic, "Quantifying infrastructure noise in agentic coding evals" (Feb 2026): 6 pp gap, p < 0.01, most vs least resourced container setup on Terminal-Bench 2.0. Takeaway: don't read a 2-3 point leaderboard gap as a harness verdict.
