My AGENTS.md

All instructions are dynamic. Always changing.

  • 🌍 Global AGENTS.md — I ask the agent to update it when something annoys me
  • 📁 Project/per-repo instructions — .planning/codebase/ regenerated when the repo changes / once asked
  • 🧩 Skills — I test new ones, keep the good, drop the rest
  • 📄 Prompt templates — a repeated task becomes a /command
  • ⚙️ Memory, models, settings — what it remembers, which model does what, how much it asks

Caveat: context files didn't reliably improve success and cost 20%+ more (ETH study). Keep only what the agent can't infer, and review what it writes into them.

~60s. None of this is written once. Every time the agent does something that annoys me, I ask it to update the right file: global AGENTS.md for how I want it to behave everywhere, the project AGENTS.md for repo specifics, a skill or prompt template for a repeated task. The .planning/codebase notes come from map-codebase. Memory (Mnemopi) changes by itself. Models and approval mode live in config.yml. Caveat: ETH Zurich, "Evaluating AGENTS.md" (arXiv 2602.11988): LLM-generated context files changed resolution by -0.5% to -2% and developer-written ones +2.4% (not significant), at +20% cost on average; instructions are followed, repository overviews don't help, and non-standard practices are where they pay off. Everything in my global file is non-inferable (who I am, comms style, rules), which is why it stays.
